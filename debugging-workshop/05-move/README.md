# 課題05：std::moveしたのにコピーが発生する

上級の発展課題です。課題04とは独立して取り組めます。

## ストーリーと仕様

大量のゲーム用リソースを次の処理へ渡します。転送処理に `std::move` が書かれているのに、実行履歴ではコピーが発生しています。

- `Resource` は整数列を所有するクラスです。
- `run_transfer` 内で用意したリソースは、転送後に元の内容を利用しません。**転送のために所有データを手放せるAPIと呼び出し側を設計する**ことが目的です。
- 対象操作は、用意済みの `source` から `destination` を構築する1回の転送です。
- この操作での `Resource` のコピー構築は0回、ムーブ構築は1回とします。名前のある既存オブジェクトから1つの転送先を構築する構造を維持します。
- 転送先は入力の要素数、全要素の値、順序を保持します。空のデータも対象です。
- 転送後の元オブジェクトのサイズや要素数は合否判定に使いません。
- `const_cast` 等で変更禁止のオブジェクトを書き換えないでください。`const` を維持すべき別用途の共有データについてはコピーが必要な場合もあり、ここでは転送用に所有したデータの設計を考えます。

## 計測の範囲

`Resource` のコピー・ムーブコンストラクタが、それぞれ回数を増やし、`COPY` / `MOVE` の履歴を出します。

1. 入力から転送元を構築する（計測外）。
2. **`Resource::reset_counts()` でリセットする。**
3. `Resource destination = transfer(std::move(source));` を実行する（計測対象）。
4. 直後に回数を取得する。
5. 確認用レポートへ全データを取り出す（計測外）。

カウンタは `Resource` の構築を数えます。入力準備やレポート生成に伴う `std::vector<int>` のコピーは対象外です。「プログラム全体でコピーがない」という測定ではありません。1回の転送を複数の入力で繰り返し、毎回リセットします。

コピー・ムーブコンストラクタのデータ処理、計測用カウンタ、リセット位置、計測範囲、公開テストを変更して成功に見せかけないでください。修正対象はAPIの受け渡し方と転送元の設計です。`exercise.hpp` の関数宣言も変更できます。

## ビルド・実行

VS 2022で `debugging-workshop` を開き、構成 **`advanced`** を選んで「すべてビルド」。スタートアップ項目 `move_demo.exe` をCtrl+F5で実行します。

WindowsのDeveloper PowerShell、Linuxのターミナルでは教材ルートから：

```sh
cmake --preset advanced
cmake --build --preset advanced --parallel 2
ctest --preset advanced -R '^move_'
```

Windows：`.\build-advanced\05-move\move_demo.exe`

Linux：`./build-advanced/05-move/move_demo`

デモは転送履歴・期待回数・実際の回数・データ比較を表示して終了します。入力メニューはありません。VSのCtrl+F5または既に開いたターミナルで結果を確認します。

単独ビルド（教材ルートから）：

```sh
cmake -S 05-move -B build-move -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build-move --parallel 2
ctest --test-dir build-move --output-on-failure
```

単独ビルドの実行ファイルはWindowsでは `build-move\move_demo.exe`、Linuxでは `build-move/move_demo` です。共通表示処理が必要なので教材フォルダー全体を配布します。

## 観察と検証

| CTest名 | 確認すること | 初期状態 |
|---|---|---|
| `move_transfer` | 各転送のコピー0回、ムーブ1回 | 失敗（コピー1回、ムーブ0回） |
| `move_data` | 空・1要素・複数要素・負数・4096要素の完全一致 | 成功 |

```sh
ctest --preset advanced -R '^move_transfer$'
ctest --preset advanced -R '^move_data$'
```

データが正しいだけでは性能上の意図まで満たしたとは限りません。一方、回数だけ正しくてもデータが壊れていれば失敗です。壁時計の実行時間は合否判定に使いません。

テストを直接実行する場合は `.\build-advanced\05-move\move_tests.exe transfer` または末尾を `data` にします。引数がない・不正な場合は終了コード2です。


## 完了条件

- 再ビルド後に両テストが成功し、各転送がコピー0回・ムーブ1回、全データ一致となる。
- `std::move` が何をするかと、今回どのコンストラクタが選ばれたかを説明する。
- 呼び出し元がデータを手放してよい理由と、変更禁止のデータを扱う別APIとの違いを説明する。
- カウンタの値を手動で調整する、データを捨てる、テストの期待値を変更する方法は不可。

## 発展問題

- `std::move` の結果の型・値カテゴリを調べる。`T&&` と `const T&&` で、できる操作はどう違うか。
- C++17のコピー省略とムーブ構築を区別する。この課題の1回という測定に任意のNRVOが必要かを調べる。
- `noexcept` の有無による `std::vector<Resource>` の再配置を別プログラムで観察する。容量・要素数・処理系を記録し、環境依存の回数を必須テストへ持ち込まない。
- ムーブ後のオブジェクトへ許される操作を、標準ライブラリの保証と自作クラスの契約に分けて説明する。「必ず空」と仮定しない。
- 値渡し、参照渡し、所有権の明示という複数のAPI設計を比較する。変更するとムーブ回数が増える設計もあるため、今回の計測契約との違いを説明する。
