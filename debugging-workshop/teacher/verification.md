# 運営者用：解答検証・開催前チェック

## 解答の検証手順

運営者用の別コピーを作り、`answers/` に記載されたファイルをその内容で置き換えます。課題の実行ソースは配布時点ではバグ入りです。テストやカウンタを変更しません。

WindowsではDeveloper PowerShell for VS 2022、Linuxではターミナルで、コピー先の `debugging-workshop` から実行します。

```sh
cmake --preset advanced
cmake --build --preset advanced --parallel 2
ctest --test-dir build-advanced --output-on-failure
```

`ctest --preset advanced` は04・05のみを選択するため、全課題の確認には上記の `--test-dir` を使います。

| 課題 | 配布版の成功判定数 | 全解答適用後 |
|---|---:|---:|
| 01 | 6/11 | 11/11 |
| 02 | 10/24 | 24/24 |
| 03 | 14/26 | 26/26 |
| 04 管理 | 5/7 | 7/7 |
| 04 初期化 | 2/5 | 5/5 |
| 05 転送回数 | 0/10 | 10/10 |
| 05 データ | 5/5 | 5/5 |

全解答適用後はCTestで7/7テスト、内部判定は88/88が成功します。初期状態は6テスト失敗、05のデータテストのみ成功です。デモの終了コードではなくCTestで判断します。

## 開催前チェック

- Windows実機でVSの構成選択、ビルド、Ctrl+F5、日本語表示、テストを確認する。
- 参加者向け版と運営者用解答を混ぜない。ブランチは閲覧権限を分離しないことを確認する。
- 段階Aは生成AI補完も停止し、段階BでAIを利用できる端末・アカウントを用意する。
- 記録シートと、AI利用前のコード・ログを保存する場所を用意する。
- ヒントは1段階ずつ提示し、経験者が操作を独占しないよう役割を交代する。
- 全問の完了を強制せず、再現条件・仮説・根拠を共有できれば成果とする。

## この資料の検証

2026-10-26、Linux / GCC 14.2 / CMake 3.31.10で、解答Markdownのコードブロックをリポジトリ外の一時コピーへ抽出して全課題をビルド・テストしました。全7テストが成功し、元の課題ソースは変更していません。Windows / Visual Studio実機は未検証です。
