# 発展課題の前提知識

最初からすべて暗記する必要はありません。コードで知らない単語を見つけたら、ここを入口に調べてください。詳しい原因の判断は、各課題の実行結果と仕様を照らし合わせて行います。

## クラス、継承、仮想関数

クラスはデータと処理をまとめた型です。`class Boss : public Enemy` は、`Boss` が `Enemy` を基にした型であることを表します。基になる型を基底クラス、そこから作る型を派生クラスと呼びます。

`virtual` は、仮想関数として呼び出し先を選べる宣言です。派生クラスの `override` は、基底クラスの仮想関数を正しく上書きしているかコンパイラに確認してもらう指定です。単語があることだけで動作を推測せず、どんなオブジェクトをどの経路で呼んでいるかも観察します。

コンストラクタは生成時、デストラクタは寿命の終わりに実行する処理です。`Enemy()` や `~Enemy()` のように書きます。クラスのメンバがいつ初期化されるかも、言語仕様の一部です。

## 値、参照、ポインタ、所有権

`T value` はT型の値、`T& ref` は既存オブジェクトを参照する変数、`T* ptr` はオブジェクトの場所を表すポインタです。参照やポインタを使うときは、参照先がまだ生きているかを考えます。

「所有権」は、誰がデータやオブジェクトの寿命を管理するかという設計上の約束です。`std::unique_ptr<T>` は単独の所有を表す標準ライブラリの型で、所有している対象を自動で破棄します。所有権を渡した後の扱いはAPIの契約を確認します。

## コピー・ムーブコンストラクタ

既存オブジェクトから新しいオブジェクトを構築するために、コピーコンストラクタ `T(const T&)` とムーブコンストラクタ `T(T&&)` を定義できます。今回の `Resource` は、各経路を通ると履歴と回数を記録します。

コピー・ムーブの「構築」と、既に存在する変数への「代入」は別の操作です。課題05は構築を対象にします。`Resource destination = ...;` は変数宣言と初期化であり、構築後の代入文ではありません。

`const` は、その経路から値を変更しないという制約です。関数名が同じでも引数型が違う関数を用意することをオーバーロードと呼びます。コンパイラは渡された式と引数型を照合して候補を選びます。

「値カテゴリ」は式の性質を分類する言語用語です。lvalue、xvalue、prvalueなどがあります。型、`const`、値カテゴリは別々の観点として整理すると調べやすくなります。
