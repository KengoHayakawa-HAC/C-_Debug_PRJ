# 課題3：円の当たり判定（上級・25～35分）

## Visual Studioの.slnで実行する

教材ルートの [DebuggingWorkshop.sln](../DebuggingWorkshop.sln) を開き、`Debug / x64` でソリューションをビルドします。`collision_demo` をスタートアッププロジェクトに設定し、Ctrl+F5で実行してください。

修正を保存・再ビルドした後、Developer PowerShellで `debugging-workshop` からテストします。

```powershell
ctest --test-dir visual-studio -C Debug --output-on-failure -R '^collision_spec$'
```

Releaseでビルドした場合は `-C Release` にします。詳しくは[共通手順](../README.md)を参照してください。以下にあるプリセット・`build-advanced`・`build-hp`等を使うコマンドは、別方式のCMakeビルド用です。

キャラクターや弾を円として扱い、2つが触れたかを判定します。見た目の描画はありません。紙に円を描いて考えても構いません。

## 仕様と必要な数学

- 円は中心 `(x,y)` と半径 `radius` で表します。中心は各軸−1000～1000、半径は0～1000の整数です。
- 円は輪郭だけでなく内部を含みます。重なっている、一方が他方に含まれる、ちょうど接している場合はすべて「当たっている」です。
- 半径0は1つの点です。点が円周上または内部なら当たっています。同じ位置の点同士も当たっています。
- AとBを入れ替えても判定は同じです。
- 中心間の距離を `d`、半径を `rA`, `rB` とすると、**dが半径の合計以下なら当たっています**。
- 三平方の定理より `d² = (xA−xB)² + (yA−yB)²`。例えば横の差3・縦の差4なら距離は5です。
- 非負の値同士は、2乗した値を比べても大小関係を判断できます。C++で2乗を書く際の演算子や書き方は調べて構いません。
- この入力範囲では差・2乗の計算はWindows/Linuxの32ビット以上の `int` に収まります。小数や範囲外の入力は今回扱いません。

| 円A (x,y,半径) | 円B (x,y,半径) | 期待する判定 |
|---|---|---|
| (0,0,2) | (10,0,2) | 当たっていない |
| (0,0,2) | (1,0,2) | 当たっている |
| (0,0,2) | (3,0,2) | 当たっている |
| (0,0,2) | (4,0,2) | 当たっている（接する） |
| (0,0,2) | (5,0,2) | 当たっていない |
| (0,0,2) | (3,4,3) | 当たっている（斜めに接する） |

## 実行方法

[共通手順](../README.md)でビルドし、VSで `collision_demo.exe` をCtrl+F5で実行します。表示の `1` は当たっている、`0` は当たっていない、です。

任意入力：メニュー `2` → `0 0 2 3 0 2`（Ax、Ay、半径A、Bx、By、半径B）。円の位置を少しずつ変え、判定が変わる境目を予想してから実行しましょう。


```sh
ctest --preset workshop -R '^collision_spec$'
```

修正後は再ビルドし、教材フォルダーからテストを実行します。テストは各入力についてA/Bの順番を逆にした判定も確認します。

## 完了条件

通常ケースだけでなく、接する場合とその前後を説明し、`collision_spec` を成功させること。

## 発展課題

半径が異なる円、同じ中心、半径0、全体を平行移動した場合などの追加テストを考案しましょう。期待値の理由も説明します。小数座標へ拡張するなら誤差をどう扱うかを考察できますが、今回は整数仕様を維持してください。
